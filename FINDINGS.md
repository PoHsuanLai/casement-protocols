## desktop-client: what the protocols cannot express

| Gap | Consequence |
| --- | --- |
| wlr-foreign-toplevel-management cannot place, move or resize a window, or move it to a workspace or Space | `DesktopCommand::Place`, `MoveToSpace` and `ActivateSpace` exist (P2-Z-dc) and `supports` is `No` for them on a compositor that does not offer `quire_desktop_v1` |
| `set_rectangle` takes a `wl_surface` of the caller's, in its surface coordinates, not a global rectangle | the caller registers surfaces with `DesktopClient::register_surface` and the command names a `SurfaceKey`; the dock's minimise target works only for a surface the client owns |
| the ext toplevel list and the wlr handle name no common id | `toplevel::pair` matches them on app id and title in arrival order; two identical windows opened together can swap identifiers. The outcome is deterministic: the first unpaired list entry takes the first unpaired managed handle, each side once (tested with identical windows). A compositor that links them (casement's Quire arm will) replaces the heuristic |
| a wlr toplevel names its outputs as `wl_output` objects, a head by name | the wire layer resolves `wl_output.name` (version 4) and everything speaks `OutputName`; a compositor with `wl_output` below 4 cannot be matched, and `DesktopClient::new` fails with `WireError::OutputTooOld` |
| the wlr toplevel protocol has no pid, no geometry and no workspace | `Toplevel` has none; cua's `pid` stays unknown and geometry must come from elsewhere (the Quire arm or the accessibility tier). Which workspace a toplevel is on is not in `ext-workspace-v1` either |
| `ext-workspace-v1` applies requests only at `commit`, and the compositor may refuse silently | `ActivateWorkspace` etc. are staged and `CommitWorkspaces` sends them; the only confirmation is the next `done` showing the new state |
| `zwlr-output-management-v1` configurations carry a serial and are cancelled if heads changed | `ConfigOutcome::Cancelled` means rebuild from the new state; `HeadConfig` lists only what the caller changes and the wire layer mentions the other enabled heads |
| `ext-image-copy-capture-v1` may offer dma-buf only | the wire layer supports shm; a compositor with no shm format fails the capture with `CaptureFailure::NoShmFormat` |
| no wlr or ext protocol says which toplevel is on which output's workspace, or a window's modality, role, emphasis | carried by `quire_desktop_window_v1` (`QuireWindow`) |

## Standing facts

- **Enum ownership across files.** An XML enum is defined once, on the interface that owns the
  concept, and other files reference it as `interface.enum`; wayland-scanner resolves that to
  `super::<interface>::<Enum>`, so each protocol module imports the interface modules of the
  protocols it names (`src/client.rs`, `src/server.rs`). `toggle` lives on
  `quire_desktop_window_v1` and the shell names it there; `glow_state` stays on
  `quire_agent_lease_v1` (its file is frozen) and the desktop window's `lease` event names it.
- **`tile_zone` is on the wire as an enum only.** No message carries it: `place_target` and
  `placement_mark` carry zones with their own codes (`place_target`'s first eight equal
  `tile_zone`'s). It is in the XML so `TileZone` has a protocol home and a generated twin.
- **Error enums have no vocab type.** They are raised by the server through the generated
  `Error` enums; nothing pure needs them. `tests/it/xml_introspection.rs` pins them instead.
- **Receipt canonical bytes.** Per item: a tag byte (motion 0, button 1, key 2, text 3,
  scroll 4), then each field little-endian (`i32`, `u32`; a text item's `fnv` as `u64`; an edge
  as its `u32` code). The digest is FNV-1a 64 over the concatenation, little-endian.
  `presses` counts button presses and `keys` key presses (releases are not counted); `events`
  counts every item. `ReceiptItem::text` builds a text item (characters are Unicode scalar
  values, the digest is over UTF-8), so both sides digest text one way.
- **The `wayland-backend` line enables `client_system`** (the pinned block's), so a build with
  either feature links the system libwayland-client.

## p2-z-dc

The Quire arm of `desktop-client`, implemented in full (this crate is "everything" at its
freeze). What it is, then what sill must change to adopt it (sill's adoption is a later lane;
sill's `desktop_wl` is not touched here).

### What landed

- `backend_for(&ProtocolSet) -> Option<DesktopBackend>`: `Quire` when `quire_desktop_manager_v1`
  and the ext list are offered, else `Wlr`, else `Ext`. Globals only. `DesktopState::backend()`.
- `Protocol::QuireShell` (`quire_shell_v1`); `Protocol::ALL` has nine entries.
- Pure model `quire::Quire` in `DesktopState::quire`: `QuireApp`, `QuireWindow`, `QuireSpace`,
  `Active`, `Shell` (modifiers, switcher, overview layout, reveals). Events are
  `DesktopEvent::Quire(QuireEvent::{App, Window, Space, Active, Shell})`.
- `reduce` projects the Quire window state onto `Toplevel.flags`, `parent` and `outputs`.
- 20 new `DesktopCommand`s (Place, MoveToSpace, AssignSpaces, ClearMinimiseTarget, the Space and
  app commands, and the shell's SetShellRole, PickSwitcher, CancelSwitcher, Overview,
  ShowDesktop). The plain window commands and `SetMinimiseTarget` change protocol with the arm
  (`requires_on`). `admit` = `supports` + "the shell role is bound".
- `client::{WaylandRoute, DesktopClient::connect, DesktopClient::with_config}` and
  `DesktopConfig`/`ShellBinding`; `FakeDesktop::with_config` and target checks.
- `desktop-client` now depends on `casement-protocols` (default features in the core, `client`
  with the wire layer). `Cargo.lock` needs regenerating by the orchestrator.

### What sill must change to adopt it

1. **Dependencies.** `sill-services`: `desktop-client = { path = "../casement-protocols/desktop-client", features = ["client"] }`
   (the shell-host/quire pinned-block rules apply: batch the re-pin). `sill-model`:
   `casement-protocols` default features only (the vocab: `WindowStateKind`, `Emphasis`,
   `PlacementMark`, `PlaceTarget`, `SpaceKind`, `Shown`, `AppLifeKind`, `Attention`,
   `ProofKind`, `MacMods`, `Corner`, `ScreenEdge`, ...). Both are consumed by path; delete the
   hand-written copies of those enums.
2. **Backend choice.** Replace `backend_for(&GlobalOffer)` with a thin call: build a
   `ProtocolSet::from_interfaces(offer.names())` and map `desktop_client::backend_for`:
   `Some(Quire) -> DesktopBackend::Quire`, `Some(Wlr | Ext) -> Wlr`, `None` -> no backend. Never from names or env.
3. **Connection.** Where the shell connects: take the fd from
   `org.quire.Compositor1.Connect("shell")` (in `sill-services`, behind the existing zbus seam)
   and call `DesktopClient::connect(WaylandRoute::Handed(fd), DesktopConfig::holding_shell())`.
   Dock/bar/overlay surfaces live in shell-host's exported connection: build the
   `DesktopClient` on that `Connection` with `DesktopClient::with_config(&conn,
   DesktopConfig::holding_shell())`, and `register_surface(&host.wl_surface(id))` for each
   (the `SurfaceKey` goes into `SetShellRole` and `SetMinimiseTarget`). Keep the
   environment route for `SILL_COMPOSITOR=kwin` runs and tests.
4. **Pump.** Poll `client.connection()`'s fd in the existing reactor; on readable call
   `dispatch_pending()` and `drain_events()`; `Desktop::state()` is the picture.
5. **Model mapping** (`DesktopView` from `DesktopState`, in `sill-services/src/desktop_wl/` and
   a pure `map.rs`):
   - `AppView` from `state.quire.apps()`: `key = app.id`, `proof = app.proof`, `life`,
     `attention`, `mru = app.mru.unwrap_or(u32::MAX)`, `visibility`, `menu`.
   - `WindowView` from `state.quire.windows()` joined to `state.toplevels.get(w.key)`:
     `identifier = toplevel.identifier`, `title`, `app` = the app id of `w.app`,
     `state = w.state`, `space` from `w.place` (`SpacePlace::On(k)` -> `quire.space(k).id`,
     `AllSpaces`, `Unknown`), `output`, `emphasis`, `placement`, plus `role`, `modality`,
     `geometry`, `responsiveness`, `lease`, `sensitivity`.
   - `SpaceView` from `state.quire.spaces()`: `id`, `kind`, `output`, `position`,
     `shown = state.space_shown(space.key)`.
   - `ActiveView`: `quire.active().app` -> app id; `.key` -> the toplevel's identifier.
   - Keep the string-keyed `sill-model` commands: resolve identifiers with
     `state.toplevels.by_identifier(&ToplevelIdentifier::new(s))`, apps with
     `quire.app_by_id`, Spaces with `quire.space_by_id`.
6. **Command mapping** (sill's `DesktopCommand` -> `desktop_client::DesktopCommand`):
   `Activate/Close/Minimise/Unminimise` -> the same names; `Place(id, target)` ->
   `Place { toplevel, target }`; `ToSpace(id, space)` -> `MoveToSpace`;
   `SwitchSpace(space)` -> `ActivateSpace`; `SetMinimiseTarget { toplevel, rect }` ->
   `SetMinimiseTarget { toplevel, surface: <the dock's SurfaceKey>, rect }` (the rect is local to
   the dock surface); add sill commands for what is new: app hide/quit/force-quit/reopen, Space
   create/remove/move, overview and show-desktop, switcher pick/cancel, window assign.
   `supports(backend, command)`: delegate to `desktop_client::supports` with the live
   `state.protocols`, or keep a pure table that matches `requires_on` (Wlr: no Place, no
   Space or app command; `SetMinimiseTarget` works on wlr through a registered surface, unlike
   sill's earlier table).
7. **Events to wire** from `DesktopEvent::Quire(QuireEvent::Shell(..))`:
   `Modifiers` -> hot corners and the Option-held dock/bar variants (keycap stays the source of
   truth for chords, `Modifiers` is the pointer-over-shell-surface view); `KeyGesture::Summon`
   -> the companion's double-tap, `HoldStart/End/Cancel` -> the hold overlay;
   `SwitcherApp/Shown/Selected/Hidden` -> the app switcher (`AppId` is the app key; answer with
   `PickSwitcher`/`CancelSwitcher`); `Overview` + `OverviewSlot/Space/Done` -> Mission Control
   chrome (`state.quire.shell().overview`); `HotCorner` -> the configured action; `Reveal` ->
   bar/dock edge reveal in full screen; `MenuFlash`, `Bell`, `Reopen` (the dock decides what
   reopening means), `Killed` (companion state). Delete `sill-overlays` `switcher/step.rs` and
   `hot_corners/step.rs` consumers of the old modifier source as S0-SW already plans.
8. **Retire.** `desktop_wl`'s own protocol code once the above passes;
   sill's copy of the pairing heuristic never existed on the Quire arm.
9. **Tests.** Drive the same mapping with `FakeDesktop::with_config` and scripted
   `QuireEvent`s (no compositor); `Linker` needs no fake.

### QUIRE-12 (lane pa2-cgate): `quire_desktop_app_v1.subject`

The item "`quire_desktop_app_v1.identity` gaining a `subject` string" is done as a new event, not a changed one, so a version 1 client is
untouched.

- `quire-desktop-v1.xml`: `quire_desktop_app_v1` is version 2 and gains the event `subject(subject: string)`, `since="2"`, appended
  after `closed` in opcode order (it is sent in the app's burst, after `identity`). The string is the program image path of a native
  process, or the sandbox's app id; the description says it is a fact the compositor established, not a claim, and that no event
  means no subject is known. `quire_desktop_manager_v1` is version 2 too, because an object a server announces is created at its
