# Findings

Open items and standing facts. An entry names the condition that closes it.

## Stubs behind frozen interfaces

`casement-protocols` itself: none. The XML, the vocab, the bindings and the receipt functions
are complete; servers and clients of the protocols live in their consumers.

`desktop-client`: filled by the P1-DC lane (reducers, `Frame::to_rgba8`, `OutputConfig::validate`,
`output::complete`, the whole wire layer). The wire layer has no test here (it needs a compositor);
the reducers, pairing, `supports`, validation, frame conversion and the fake are covered by
`desktop-client/tests/it`.

## desktop-client: what the protocols cannot express

| Gap | Consequence |
| --- | --- |
| wlr-foreign-toplevel-management cannot place, move or resize a window, or move it to a workspace or Space | `DesktopCommand` has no `Place`, `ToSpace` or `SwitchSpace`; sill's `supports(Wlr, Place)` is `No`. The Quire arm (P2) adds them |
| `set_rectangle` takes a `wl_surface` of the caller's, in its surface coordinates, not a global rectangle | the caller registers surfaces with `DesktopClient::register_surface` and the command names a `SurfaceKey`; the dock's minimise target works only for a surface the client owns |
| the ext toplevel list and the wlr handle name no common id | `toplevel::pair` matches them on app id and title in arrival order; two identical windows opened together can swap identifiers. The outcome is deterministic: the first unpaired list entry takes the first unpaired managed handle, each side once (tested with identical windows). A compositor that links them (casement's Quire arm will) replaces the heuristic |
| a wlr toplevel names its outputs as `wl_output` objects, a head by name | the wire layer resolves `wl_output.name` (version 4) and everything speaks `OutputName`; a compositor with `wl_output` below 4 cannot be matched, and `DesktopClient::new` fails with `WireError::OutputTooOld` |
| the wlr toplevel protocol has no pid, no geometry and no workspace | `Toplevel` has none; cua's `pid` stays unknown and geometry must come from elsewhere (the Quire arm or the accessibility tier). Which workspace a toplevel is on is not in `ext-workspace-v1` either |
| `ext-workspace-v1` applies requests only at `commit`, and the compositor may refuse silently | `ActivateWorkspace` etc. are staged and `CommitWorkspaces` sends them; the only confirmation is the next `done` showing the new state |
| `zwlr-output-management-v1` configurations carry a serial and are cancelled if heads changed | `ConfigOutcome::Cancelled` means rebuild from the new state; `HeadConfig` lists only what the caller changes and the wire layer mentions the other enabled heads |
| `ext-image-copy-capture-v1` may offer dma-buf only | the wire layer supports shm; a compositor with no shm format fails the capture with `CaptureFailure::NoShmFormat` |
| no protocol here says which toplevel is on which output's workspace, or a window's modality, role, emphasis | belongs to the Quire arm |

## Standing facts

- **Enum ownership across files.** An XML enum is defined once, on the interface that owns the
  concept, and other files reference it as `interface.enum`; wayland-scanner resolves that to
  `super::<interface>::<Enum>`, so each protocol module imports the interface modules of the
  protocols it names (`src/client.rs`, `src/server.rs`). `toggle` lives on
  `quire_desktop_window_v1` and the shell names it there; `glow_state` stays on
  `quire_agent_lease_v1` (its file is frozen) and the desktop window's `lease` event names it.
- **`tile_zone` is on the wire as an enum only.** No message carries it: `place_target` and
  `placement_mark` carry zones with their own codes (`place_target`'s first eight equal
  `tile_zone`'s). It is in the XML so `TileZone` has a protocol home and a generated twin.
- **Error enums have no vocab type.** They are raised by the server through the generated
  `Error` enums; nothing pure needs them. `tests/it/xml_introspection.rs` pins them instead.
- **Receipt canonical bytes.** Per item: a tag byte (motion 0, button 1, key 2, text 3,
  scroll 4), then each field little-endian (`i32`, `u32`; a text item's `fnv` as `u64`; an edge
  as its `u32` code). The digest is FNV-1a 64 over the concatenation, little-endian.
  `presses` counts button presses and `keys` key presses (releases are not counted); `events`
  counts every item. `ReceiptItem::text` builds a text item (characters are Unicode scalar
  values, the digest is over UTF-8), so both sides digest text one way.
- **The `wayland-backend` line enables `client_system`** (the pinned block's), so a build with
  either feature links the system libwayland-client.
